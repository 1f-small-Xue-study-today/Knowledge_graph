01 / The big picture

Learn to explain data—and then create new data.

An ordinary autoencoder compresses an input x into a code z and decodes that code back into a reconstruction. A VAE adds a probabilistic model: for each input, its encoder predicts a distribution of possible codes.

Input x
an observed example→Encoder qφ(z|x)
predict μ and σ→Sample z
one possible code→Decoder pθ(x|z)
predict a data distribution

Think of a photo as being explained by hidden factors such as pose and lighting. A latent vector z can represent useful variation, but its coordinates are not automatically named factors like “pose” or “color.” Learning interpretable, independent factors is an additional challenge.

Training: an input is available

Encode a real example, sample a code, decode it, and adjust both networks. Reward explaining the input; penalize the encoder distribution for departing from the prior.

Generation: no input is needed

Sample a new code from the prior p(z), usually N(0,I), and pass it through the trained decoder. The encoder is not needed for unconditional generation.

Why not just sample arbitrary codes in an ordinary autoencoder? Its training does not ensure those codes lie in regions where the decoder has learned useful outputs. The VAE’s prior penalty encourages overlap between encoded regions and the region we will sample at generation time. It helps; it does not guarantee perfect samples everywhere.

02 / What the encoder returns

One input becomes a cloud of possible codes.

qφ(z|x) = N(μφ(x), diag(σ²φ(x)))

For a d-dimensional latent code, the encoder usually returns two d-dimensional vectors: the mean μ and the log variance ℓ = log σ². Convert back with σ = exp(ℓ/2). Predicting log variance permits unconstrained network outputs while ensuring positive variance.

ObjectPlain meaningLearned?
p(z) = N(0,I)Prior: where to sample codes before seeing an inputFixed in this standard VAE
qφ(z|x)Encoder: approximate posterior for one inputYes, parameters φ
pθ(x|z)Decoder: distribution over data given a codeYes, parameters θ
pθ(z|x)True posterior implied by the model and Bayes’ ruleDetermined by θ; usually hard to compute

“Variational” means we select a tractable family q and optimize its parameters to approximate a difficult posterior. One encoder network produces the approximation for every input; this sharing is called amortized inference.

A diagonal Gaussian assumes latent coordinates are independent within q(z|x) for a fixed input. It does not imply that the codes aggregated across the entire dataset are independent.

Why write z = μ + σ ε?

The direct instruction “sample from N(μ,σ²)” hides how a sample depends on the parameters. Instead, draw parameter-independent noise ε ∼ N(0,1), then transform it:

ε ∼ N(0,1),   z = μ + σ ε
∂z/∂μ = 1,   ∂z/∂σ = ε

Try this: leave ε fixed and move μ. The sampled z moves smoothly one-for-one. Now move σ: the effect depends on ε. Gradients can travel through these arithmetic operations back into the encoder. During training we usually draw fresh noise; holding it fixed here isolates the dependency.

This is the reparameterization trick（重参数化）. It does not remove randomness. It expresses the randomness in a form that supports a pathwise gradient estimator.

Worked gradient: how does reconstruction teach the encoder?

Suppose the decoder mean is ŵ = 2z and the reconstruction loss is R = (x − 2z)²/2. Then ∂R/∂z = 2(2z − x). Through z = μ + σε, we get ∂R/∂μ = 2(2z − x) and ∂R/∂σ = 2(2z − x)ε. The KL term adds its own gradients. For a network predicting ℓ = log σ², ∂z/∂ℓ = σε/2.

04 / Why the model learns

A reward for explaining. A penalty for drifting.

ELBO(x) = Eq(z|x)[log pθ(x|z)] − KL(q(z|x) ‖ p(z))
Loss(x) = −ELBO(x) = reconstruction NLL + prior KL

NLL means negative log likelihood. The reconstruction term asks: “Does the decoder assign high probability to the original x?” The KL asks: “How far has this input’s encoder distribution moved from our prior?”

For a diagonal Gaussian encoder and standard Gaussian prior:

KL = ½ Σⱼ (μⱼ² + σⱼ² − 1 − log σⱼ²)

Means far from zero are penalized. Variances much larger or much smaller than 1 are penalized. Notice in the sampling lab that σ approaching zero increases KL: the regularizer does not simply ask for narrow clouds.

Reconstruction depends on the likelihood

A Gaussian decoder with fixed variance τ² has NLL proportional to squared error, plus a constant. A Bernoulli decoder for binary data uses binary cross-entropy. A decoder outputs distribution parameters; its displayed mean is not a full random sample.

There are still two different KL terms

Prior KL is part of the loss. Posterior KL measures the bound’s gap:

log pθ(x) − ELBO(x)
= KL(q(z|x) ‖ pθ(z|x))

Matching the prior is not the same as matching the true posterior.

What does β change?

Lβ = reconstruction NLL + β × prior KL

β = 1 gives the standard negative ELBO. Other weights change the objective (often called a β-VAE objective). A higher weight emphasizes prior matching; it can reduce information carried by z and worsen reconstruction. It does not guarantee disentanglement. Changing β changes the score’s definition, so compare training progress at a fixed β.

05 / Interactive lab · real optimization

Train a tiny VAE you can inspect completely.

Our dataset contains eight numbers: −2, −1.5, −1, −0.5, 0.5, 1, 1.5, 2. The encoder and decoder are linear, with one latent coordinate. This is a deliberately limited VAE—not a simulation of a large image network.

q(z|x) = N(ax + b, exp(ℓ))
p(x|z) = N(wz + c, τ²),   τ = 0.5
p(z) = N(0,1)

Five parameters a, b, ℓ, w, c are learned. Because everything is linear Gaussian, we can compute the reconstruction expectation exactly instead of estimating it with random samples. The optimizer below performs actual full-batch gradient descent on this objective:

R(x) = [(x − wμ − c)² + w²σ²] / (2τ²) + ½ log(2πτ²)
K(x) = ½(μ² + σ² − 1 − log σ²),   μ = ax + b
Lβ = average over data of [R(x) + βK(x)]

Learning rate: 0.01. Changing β resets the loss-history plot, but keeps the current weights. Reset weights before comparing runs from the same starting point.

Experiment: reset and train with β = 1. Then reset, choose β = 10, and train again. Watch the encoder slope a and decoder slope w shrink: under strong prior pressure, the model can stop using the input. This illustrates posterior collapse—q approaches the prior and z carries little information about x. With β = 0, reconstruction dominates and there is no pressure to match the prior.

How is the exact likelihood and ELBO gap checked here?

This special model has marginal p(x) = N(c,w²+τ²). We compute its average log likelihood directly. We also compute the standard ELBO = −(R+K), even when β differs from 1. The displayed gap is average log likelihood minus this standard ELBO, and must be nonnegative up to roundoff. In a nonlinear VAE, the exact likelihood usually cannot be computed this way.

Moving smoothly between two latent values is interpolation. In this toy decoder, the output changes linearly. A neural decoder can learn a nonlinear transformation, but smooth interpolation is not a guarantee that every intermediate output is realistic.

This model can only generate one Gaussian distribution over numbers: p(x) = N(c,w²+τ²). It cannot learn two separate peaks or generate images. The small example exposes the mechanics; expressive neural networks and suitable data are needed for richer models.
07 / Read a training loop

Match each line to a part of the story.

The following is framework-style pseudocode for a diagonal-Gaussian VAE with a fixed-variance Gaussian decoder. Here x has shape [batch, data dimensions]; μ and logvar have shape [batch, latent dimensions].

# One minibatch; encoder and decoder both have trainable parameters
mu, logvar = encoder(x)
std = exp(0.5 * logvar)
eps = standard_normal_like(std)
z = mu + std * eps                  # reparameterization
x_mean = decoder(z)                 # Gaussian likelihood mean

# Sum dimensions within each example, then average examples.
# Gaussian constant omitted: it does not affect gradients for fixed tau.
recon = sum_over_data_dims((x - x_mean)**2 / (2 * tau**2))
kl = 0.5 * sum_over_latent_dims(mu**2 + exp(logvar) - 1 - logvar)
loss = mean_over_batch(recon + kl)   # beta = 1

optimizer.zero_grad()
loss.backward()                     # updates both networks' gradients
optimizer.step()

# Generation after training: no encoder or original x required
z_new = standard_normal([number_of_samples, latent_dimensions])
x_mean_new = decoder(z_new)
x_new = x_mean_new + tau * standard_normal_like(x_mean_new)

One sampled z per input gives a Monte Carlo estimate of the reconstruction expectation; the Gaussian KL can be computed exactly. More samples can reduce estimation noise at additional cost.

Common implementation mistakes

  • Using exp(logvar) as the standard deviation. It is the variance; use exp(logvar/2) to sample.
  • Subtracting KL in the minimized loss. Subtract it in the maximized ELBO; add it in negative ELBO.
  • Averaging reconstruction over pixels while summing KL over latent dimensions without accounting for the scale change. This changes their effective balance.
  • Detaching z or μ from the gradient computation. The reconstruction gradient must reach the encoder.
  • Using binary cross-entropy for arbitrary continuous data without considering the likelihood assumption.
  • Interpreting a low KL alone as success. It can also mean the latent representation carries little information.

A practical first nonlinear project is a small VAE on binary or grayscale handwritten digits with a two-dimensional latent space. Evaluate reconstruction, generated samples, and both loss components; a decreasing total loss alone does not establish sample quality.

08 / Active recall

Explain it without looking at the formulas.

1. Does the encoder return a sample or a distribution?

It usually returns parameters μ and log σ² defining q(z|x). A subsequent sampling operation constructs z. Encoding with μ alone is a deterministic summary, not a posterior sample.

2. Why keep the encoder if generation only uses the decoder?

During training it proposes plausible latent explanations for each observed x, making the variational bound tractable to optimize. After training it is also useful for reconstruction and representation tasks.

3. If μ = 0 and σ = 1, is the VAE fully trained?

No. The prior KL is zero, but the decoder may reconstruct poorly. If all inputs have this same q, the sampled code conveys no input-specific information.

4. Let μ = 1, σ = 0.5, ε = −2. What is z? What is prior KL?

z = 1 + 0.5(−2) = 0. KL = ½(1 + 0.25 − 1 − log 0.25) ≈ 0.8181 nats. A sampled z of zero does not mean the whole encoder distribution matches the prior.

5. Can I obtain a full data sample just by displaying the decoder mean?

The mean is a useful deterministic output, but a full probabilistic sample also draws from p(x|z). For our toy model, add Gaussian noise with standard deviation τ = 0.5.

6. Why can a VAE produce blurry images?

A simple factorized Gaussian decoder and limited representation can favor averaged predictions where details are uncertain. Decoder likelihood, model capacity, optimization, and the KL tradeoff all matter; blurriness is not an unavoidable property of every VAE.

7. Is a larger ELBO always proof of larger likelihood when both networks change?

No. The bound can tighten while likelihood changes differently. log p(x) = ELBO + posterior KL; both terms can change. At fixed θ, improving q tightens the bound without changing the model likelihood.

You have the core foundation when you can trace x → (μ,σ) → z → p(x|z), explain the two loss terms, and describe how generation works without an input.
